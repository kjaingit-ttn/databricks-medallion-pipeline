# Design Specification — Medallion E-Commerce Pipeline

Design specification effectively followed during AI-assisted development of `databricks-medallion-pipeline`. Grounded in implemented code and verified Databricks/local runs.

---

## 1. Objective

Build a reproducible **Databricks Medallion Architecture** pipeline that:

1. Ingests synthetic e-commerce CSVs (customers, orders, products)
2. Preserves all raw rows in Bronze
3. Flags data-quality issues in Silver without deletion
4. Produces business aggregations in Gold from PASS-quality data
5. Powers a Databricks SQL Dashboard for stakeholders

---

## 2. Architecture

```
CSV (Volume) → Bronze (raw Delta) → Silver (flagged Delta) → Gold (aggregations) → Dashboard (SQL viz)
```

| Layer | Schema | Responsibility |
|-------|--------|----------------|
| Bronze | `bronze` | Raw landing; explicit StringType; lineage metadata |
| Silver | `silver` | Quality flags; `quality_check_result`; canonical dedup |
| Gold | `gold` | PASS-only business metrics (with documented exceptions) |
| Dashboard | — | Reads `gold.*` and `silver.data_quality_report` |

---

## 4. Bronze specification

- **No transformations** — filter, cast, dedupe forbidden
- **Explicit schemas** — all business columns `StringType`
- **Metadata:** `_ingest_timestamp`, `_source_file` via `_metadata.file_path` (UC-safe)
- **Audit:** `bronze.ingestion_log` per ingest run
- **Scripts:** `01_ingest_customers.py`, `02_ingest_orders.py`, `03_ingest_products.py`

---

## 5. Silver specification

### Quality check categories (4)

| # | Module | Flags |
|---|--------|-------|
| 1 | Completeness | `chk_completeness_email`, `chk_completeness_customer_id`, `chk_completeness_product_id` |
| 2 | Uniqueness | `chk_uniqueness_customer_id`, `chk_uniqueness_order_id` |
| 3 | Referential integrity | `chk_ref_customer_exists`, `chk_ref_product_exists` |
| 4 | Business logic | Amount consistency, completed payment, positive quantity, signup not future, positive price/cost |

### Rules

- `chk_* = True` means check **passed**
- **Never drop rows** — all Bronze rows retained
- `quality_check_result = 'PASS'` when all relevant flags are True
- **Canonical tables:** `silver.customers_canonical` (10,000), `silver.orders_canonical` (100,000) — first-seen by `_ingest_timestamp`
- **Orchestrator:** `create_silver_tables.py` → `silver.data_quality_report`

### Verified failure counts (orders)

420 FAIL rows = 100 + 200 + 50 + 30 + 40 (uniqueness on duplicate-key pairs)

## 6. Gold specification

### Filtering strategy

- **Default:** `quality_check_result = 'PASS'` AND non-Cancelled orders
- **Canonical join:** `orders_canonical` / `customers_canonical` joined to `silver.orders` / `silver.customers` on business key + lineage columns
- **Exception:** `gold.order_status_funnel` uses all `silver.orders`

### Required aggregations (3)

| Table | Grain |
|-------|-------|
| `gold.sales_by_product` | Product revenue, orders, AOV, units |
| `gold.revenue_by_customer` | Customer revenue, orders, `lifetime_value_actual` |
| `gold.customer_segmentation` | High-Value / Repeat / One-Time / Inactive |

### Additional aggregations (4)

| Table | Purpose |
|-------|---------|
| `gold.daily_revenue_trend` | Daily + weekly revenue trend |
| `gold.revenue_by_category` | Category rollup |
| `gold.order_status_funnel` | Operational status mix |
| `gold.top_customers_by_frequency` | Top 20 by order count |

### Verified row counts (local = Databricks)

500, 9,940, 960, 4, 10, 3, 20

## 8. Testing specification

- **Framework:** pytest + local PySpark 3.5.1
- **Scope:** 36 tests importing real `src/silver/` modules
- **Assertions:** Exact defect counts; row-count preservation; canonical dedup; orchestrator rollup
- **Command:** `pytest -v`

---

## 9. Databricks deployment specification

- **Runners:** Self-contained `run_*_databricks.py` — one file per notebook cell, no sibling imports
- **Storage:** Delta Lake managed tables in Unity Catalog schemas
- **Landing zone:** `/Volumes/workspace/raw_landing/landing_zone/`
- **Local-first:** Prove logic in `create_gold_tables.py` / pytest before workspace run

---

## 10. Non-goals (out of scope)

- Real PII or production data sources
- Scheduled Databricks Jobs / Asset Bundles (manual notebook run documented instead)
- Parameterized dashboard filters on pre-aggregated Gold tables
