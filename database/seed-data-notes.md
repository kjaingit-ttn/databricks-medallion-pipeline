# Seed Data Notes

Summary of the three synthetic CSV files in `data/`, generated by `src/data_generation/generate_sample_data.py`. Defect counts are fixed and reproducible for a given `--seed` (default `42`); see `src/data_generation/DATA_GENERATION_NOTES.md` for design rationale.

## Files and row counts

| File | Base rows generated | Duplicate rows appended | **Final row count** |
|------|--------------------:|------------------------:|--------------------:|
| `data/customers.csv` | 10,000 | +10 | **10,010** |
| `data/orders.csv` | 100,000 | +20 | **100,020** |
| `data/products.csv` | 500 | 0 | **500** |

Duplicate rows reuse an existing `customer_id` or `order_id` as a **second appended row** (not an in-place overwrite), matching real replay/correction patterns and exercising Bronze “keep everything” plus Silver uniqueness checks.

## Source columns (CSV headers)

**customers.csv:** `customer_id`, `customer_name`, `email`, `country`, `signup_date`, `customer_segment`, `lifetime_value`

**orders.csv:** `order_id`, `customer_id`, `order_date`, `product_id`, `quantity`, `unit_price`, `total_amount`, `order_status`, `payment_date`

**products.csv:** `product_id`, `product_name`, `category`, `price`, `cost`, `stock_quantity`, `reorder_level`

## Intentional data quality defects injected

All counts below are verified by the data generator’s post-write summary and by local/Databricks Silver checks.

| Defect | Table / column | Count | Silver check(s) affected |
|--------|----------------|------:|--------------------------|
| Null email | `customers.email` | **50** | `chk_completeness_email` |
| Duplicate `customer_id` rows | `customers.customer_id` | **10** extra rows (10,010 total) | `chk_uniqueness_customer_id` |
| Null `customer_id` | `orders.customer_id` | **100** | `chk_completeness_customer_id` |
| Null `product_id` | `orders.product_id` | **200** | `chk_completeness_product_id` |
| Orphan `customer_id` | `orders.customer_id` | **50** | `chk_ref_customer_exists` |
| Orphan `product_id` | `orders.product_id` | **30** | `chk_ref_product_exists` |
| Duplicate `order_id` rows | `orders.order_id` | **20** extra rows (100,020 total) | `chk_uniqueness_order_id` |

Orphan foreign keys use IDs **above valid ranges** (`customer_id` ≥ 99,001; `product_id` ≥ 9,901) so they cannot accidentally match a legitimate dimension row.

## Defects not injected (verified zero failures)

The generator does **not** inject business-logic defects. After Silver business-logic checks, the sample data shows **0 failures** for:

- `chk_biz_amount_consistency` (orders)
- `chk_biz_completed_has_payment` (orders)
- `chk_biz_positive_quantity` (orders)
- `chk_biz_signup_not_future` (customers)

Products have **no injected defects**; all 500 product rows pass `chk_biz_positive_price` and `quality_check_result = 'PASS'`.

## Regenerating seed data

From the project root:

```bash
pip install -r requirements-dev.txt
python src/data_generation/generate_sample_data.py --seed 42
```

The script prints a verification block comparing actual null, duplicate, and orphan counts to the expected values above. After regeneration, re-upload CSVs to the Databricks landing volume (see `database/setup-notes.md` and `database/DATABRICKS_CLI_SETUP.md`).
